# 通用可执行触觉技能记忆：研究想法与验证边界

目标是证明一套通用流程：由 LLM 根据任务、公开观测和环境 API 自主生成策略，从执行中形成技能记忆，并在后续实例或任务中检索、验证和适配。技能是 LLM 推理与接触经验产生的结果；框架不预先写好钢琴 play_note、固定阶段分解或每个任务的最佳参数。

## 通用流程

1. **生成**：任务及公开 API、当前视觉和触觉交给 LLM，由它决定策略和代码组织。
2. **形成记忆**：保存可参数化代码、可变参数、适用条件、接口/传感器版本，以及与该技能对应的公开触觉和动作依据。
3. **检索与验证**：按能力、接触状态和接口兼容性检索；用本次新触觉验证旧经验，不把历史观测当成当前事实。
4. **执行与局部适配**：兼容技能在本地直接执行，不上传源码和状态；存在明确公开失败时，再给 LLM 相关函数及简短证据，局部修复。
5. **版本更新**：保留修改来源、验证状态、父版本和拒绝/回退记录，避免把未验证建议宣称为成功技能。

跨机器人或 API 不兼容时，允许 LLM 做适配，而不是强行执行旧代码。环境可以提供底层 API、观测含义和安全边界，但不把专家策略写成记忆框架的内置答案。

## 触觉贡献的识别

历史触觉应影响检索哪项技能、如何调整参数、是否继续复用；仅保存代码并读取当前触觉，主要证明代码缓存收益，尚不能证明历史触觉记忆收益。传感器标定与触觉记忆分别报告；钢琴键顶接触力与弹力带张力虽同为牛顿，物理含义与权重不能混用。

至少比较四组，并保持当前触觉、力估计器、释放保护、模型及预算一致：

| 实验组 | 可使用的历史内容 |
|---|---|
| 无记忆 | 每次重新推理 |
| 代码记忆 | 代码和参数，不提供历史触觉依据 |
| 文字触觉记忆 | 历史触觉经验的文字总结 |
| 可执行触觉记忆 | 代码、参数、触觉历史及适用条件 |

正常复用的 API 开销应为零；触觉与机器人状态不应作为每次复用的模型输入。只有定位新场景或修复具体问题时才请求模型。修复输入只保留一份相关源码、必要的失败阶段摘要和邻近动作，不重复附整段程序和大量关节数组。

## 证据与当前状态

不同音序的钢琴实验只能证明同任务跨实例复用。要支持通用性，需要多个不同接触任务使用同一套生成、存储、检索、验证与适配流程，并加入留出任务测试；不能由单一钢琴实验推断适用于所有任务。

报告每组原生成绩、动作数、所有生成/维护/修复 token、缓存命中、实际执行版本及控制失败。不能把提前中止造成的低动作数当成效率提升；不能把新增护栏带来的收益都归因于记忆。逐帧真实力和原生判分只用于独立离线审计，不输入策略、检索、修复或记忆晋升。

当前工程实现仍是钢琴专用可执行代码缓存，是通用框架的工程验证实例，不是通用流程已经完成的证明。原十组实验于 2026-10-25 暂停，保留 3300–3304 的结果及 3305 中断现场。后续先做单独 3302 诊断，再决定通用框架实现；不自动恢复原队列。
